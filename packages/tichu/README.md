# @mightichu/tichu

티츄(4인 2:2) 룰 엔진. 순수 함수, 런타임 의존성은 `@mightichu/core` 뿐.

규칙은 [docs/rules-tichu.md](../../docs/rules-tichu.md) — 공식 룰북(Fata Morgana/ABACUSSPIELE) 기준.

| 모듈 | 역할 |
|---|---|
| `cards.ts` | 56장 덱, 토큰, 특수카드(용·봉황·개·참새), 점수 |
| `combos.ts` | **조합 판정** — 엔진에서 가장 까다로운 부분 |
| `scoring.ts` | 팀 점수, 티츄 선언 가감, 더블윈 200 |
| `engine.ts` | `GameEngine` 구현 — 상태 전이와 리댁션 |

## 상태 흐름

```
GRAND(8장) → EXCHANGE(14장, 3명에게 1장씩) → PLAY → DONE
                                              ↳ DRAGON_GIFT (용으로 먹었을 때)
```

## 조합 판정 — 봉황은 대입 열거로 푼다

봉황은 2~A 와일드카드다. 특수 규칙을 조합 인식기 안에 끼워 넣으면 반드시 틀린다.
대신 **봉황을 끗 r 로 바꾼 가상 손패에 평범한 열거기를 돌리고 합친 뒤 중복을 지운다.**

```
for r in 2..14:
    plainCombos([...손패에서 봉황 제외, 봉황을 r 로 대입])
```

비교값(`rank2`)은 **2배 정수 스케일**이다 — 봉황 싱글의 "직전보다 ½ 높음" 을
부동소수점 없이 다루기 위해. 일반 끗 r 은 2r, 봉황은 홀수값을 갖는다.

## 구현에서 걸렸던 것

실제로 테스트가 잡아낸 버그들이다. 전부 조용히 틀렸을 수 있는 종류다.

- **스트레이트 플러시가 폭탄으로 인식되지 않음** — 같은 카드가 `STRAIGHT` 와
  `BOMB_STRAIGHT` 두 해석을 갖는데 끗이 같아 먼저 생성된 쪽이 뽑혔다.
  → `parseCards` 가 폭탄을 우선한다. 룰상 "평범한 스트레이트로 내기" 는 선택지가 아니다.
- **용 양도 대기 중 라운드가 끝나면 그 트릭 점수가 사라짐**
  → `settleIfOver` 는 `dragonGift` 가 남아 있으면 끝내지 않는다.
- **마지막 사람이 트릭 도중에 나가면 테이블 위 카드가 사라짐**
  → 끝내기 전에 열린 트릭을 먼저 닫는다.

## 설계 메모

- **진행 방향은 반시계(ccw)** — 공식 룰. 좌석 배열은 시계방향 물리 배치로 두고 방향만 바꾼다
- `legalActions` 는 턴을 묻지 않는다 — 폭탄(아웃 오브 턴)과 스몰 티츄 선언이
  비차례 플레이어의 합법 수로 그냥 나타난다. 인터럽트 개념이 필요 없다
- **교환은 받는 사람별 `GIVE` 한 장씩.** 한 번에 묶으면 합법 수가 2000가지를 넘는다
- `legalPlays` 는 대표 선택(같은 끗이면 무늬 순서가 앞선 카드)만 돌려준다.
  사람이 고른 동등한 다른 조합은 `parseCards` 로 직접 검증한다
