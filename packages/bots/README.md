# @mightichu/bots

AI 봇. 입력은 **리댁션된 View** 뿐이라 구조적으로 치팅이 불가능하다.

```ts
type Bot<View, Action> = {
  decide(ctx: { me, view, legal, rng }): Action;   // View 만 받는다 — State 가 아니다
  wants?(ctx): boolean;                            // 지금 꼭 둬야 하는가
}
```

## 레벨

| | 용도 | 상태 |
|---|---|---|
| **L1 랜덤** | 엔진 테스트 하네스 | ✅ |
| **L2 휴리스틱** | 실제 대전 상대 | ✅ |
| L3 MCTS + 결정화 | 강한 AI | ⬜ 별도 과제 |

## 임계값은 추측이 아니라 측정으로 잡는다

휴리스틱의 상수를 감으로 정하면 틀려도 모른다. 전부 자동 대국으로 재서 맞췄다.

### 마이티 — 공약 추정

점수를 가져오는 경로는 둘뿐이다: 기루다로 베어내기, 내 무늬 높은 카드로 직접 먹기.
그래서 **기루다 장수**가 거의 전부다.

기준 상수를 7 로 뒀을 때와 6 으로 내렸을 때 (500판):

| 기준 | 여당 성공률 | 평균 공약 | 평균 획득 | 시점 |
|---|---|---|---|---|
| 7 | 46.0% | 15.18 | 14.04 | 초기 |
| 6 | 57.2% | 14.20 | 14.00 | 공약 보정 후 |
| **5** | **56.8%** | **13.39** | **13.35** | 보이드·야당연대로 수비가 세진 뒤 |

**수비가 세질수록 이 값도 내려가야 한다.** 같은 손패로 딸 수 있는 점수가 줄기 때문이다 —
실제로 야당 연대를 넣자 성공률이 48% 로 떨어져 다시 내렸다.

### 티츄 — 선언 판단

`planHand` 로 손패를 낼 단위로 쪼개 **lotCount**(손을 비우는 데 필요한 횟수)와
**control**(용·봉황·에이스·폭탄 개수)을 센다. 600판 측정 (±100 이므로 손익분기 50%):

| 조건 | 선언 수 | 성공률 | 판당 EV |
|---|---|---|---|
| lot≤3 ctrl≥2 | 13 | 69.2% | +0.8 |
| **lot≤5 ctrl≥3** | **53** | **52.8%** | **+0.5** |
| lot≤5 ctrl≥2 | 150 | 48.7% | −0.7 |
| lot≤6 ctrl≥3 | 115 | 46.1% | −1.5 |

표본이 받쳐주면서 +EV 인 조건을 택했다.

**선언 시점도 측정으로 바뀌었다.** 교환 **전** 손패로 재면 받을 3장을 모르는 채
재는 셈이라 성공률이 37% 로 떨어진다. 룰상 첫 카드를 내기 전이면 언제든 선언할 수 있으므로
교환이 끝난 뒤에 판단한다.

> 솔직한 평가: 티츄 선언 +0.5/판은 **미미하다.** 병목은 선언 규칙이 아니라 플레이 실력이다.
> 봇이 더 잘 두게 되면 같은 조건에서 성공률이 올라가고, 그때 기준을 완화하면 된다.

## L2 가 하는 것

**공통**
- **팀 패를 밟지 않는다.** 파트너가 이기고 있으면 넘긴다 (200판 자동 대국으로 0회 검증)
- **카운팅** — `view.playedCards`(공개 정보)를 보고 내 카드가 최고인지 안다

**티츄** (`tichu/plan.ts`)
- **핸드 분할** — 14장을 낼 단위로 미리 쪼갠다. 스트레이트가 될 카드를 홑장으로 흘리지 않는다
- 폭탄은 깨지 않고 통째로 남긴다
- 교환: 파트너에게 센 카드, 상대에게 약한 카드
- 파트너가 티츄를 부르면 **길을 터준다** (점수 큰 트릭만 챙기고 나머지는 양보)
- 아웃오브턴 폭탄은 큰 트릭에서만

**마이티**
- 기루다 장수 기반 공약 추정
- 확실히 먹을 수 있는 카드(같은 무늬 상위가 전부 나감)로 리드
- 아는 범위에서 아군 추론 (프렌드가 숨어 있어 범위가 좁다)

## 판 읽기 (`mighty/read.ts`)

남의 손패는 못 보지만 **누가 어느 무늬를 못 따라갔는지는 모두가 봤다.**

- `knownVoids` — 리드 무늬를 안 따라갔으면 그 무늬가 없다.
  단 마이티·조커는 아무 때나 낼 수 있으므로 근거가 되지 않는다
- `ruffRisk` — 상대가 보이드인 무늬를 리드하면 기루다에 잘린다. 그런 무늬는 뒤로 민다
- `likelyAlly` — **야당 입장에서 주공이 아닌 나머지 셋은 "프렌드 1 + 야당 2"**,
  즉 2/3 확률로 같은 편이다. 야당끼리 서로 잡아먹는 게 가장 큰 손해라
  주공이 이기는 게 아니라면 굳이 밟지 않는다

## 정석(사람의 관례) 반영

검색해서 찾은 실제 플레이 관례를 넣고, **전부 A/B 로 효과를 쟀다.**
"정석이라니까 좋겠지" 로 넣으면 오히려 나빠지는 경우가 실제로 있었다.

### 마이티

| 관례 | 근거 |
|---|---|
| **프렌드는 선을 잡으면 낮은 기루다를 돌린다** | 낮아야 주공이 마이티·높은 기루다로 회수하며 야당 기루다를 뽑는다. 높은 걸 내면 주공이 회수할 수 없다 |
| **야당의 마공** — 마이티 무늬를 친다 | 마이티는 자기 무늬가 리드되고 그 무늬가 그것뿐이면 반드시 나온다. 계속 치면 끌려 나온다 |

A/B (신규 2명 vs 구버전 3명, 1인 평균, 제로섬이라 0 기준, 600판):

```
신규(전부 켬)   -0.09
구버전(전부 끔) -0.26     → 신규가 약 0.17 우위
프렌드 기루다만 -0.09     → 이득의 대부분이 여기서 나온다
마공만          -0.16     → 거의 안 걸린다(야당이 선을 잡을 땐 이미 마이티가 나온 뒤가 많다)
```

### 티츄

| 관례 | 효과 |
|---|---|
| **딱 한 단계 위로만 이긴다** | 에이스로 3을 잡으면 정작 필요할 때 없다 |
| **용 트릭은 "오른쪽 상대"에게** | 각자 한 번씩 선을 잡으면 그 사람이 가장 늦게 나간다 |
| **상대가 티츄를 부르면 폭탄으로 저지** | ±100 을 뒤집는 일이라 트릭 점수보다 가치가 크다 |

A/B (정면 대결, 팀 점수 차, 500판. 양수 = 켠 쪽 유리):

```
전부 켬 vs 전부 끔   +1.7
폭탄저지만 끔        +4.3
최소단계만 끔        +3.6
용-오른쪽만 끔       +2.6
```

### ⚠️ 정석을 그대로 넣었다가 크게 손해 본 사례

"A+봉황 / A+용 / 에이스 3장이면 티츄를 부른다" 는 통용 기준은 **첫 8장 기준**이다.
14장 전체에 적용했더니:

```
선언 58 → 469,  성공률 53% → 36%,  판당 EV +0.67 → -22.17
```

에이스 3장만으로 완화해도 성공 48.0% / 판당 −0.67 로 여전히 손해였다.
**측정으로 잡은 기준(lotCount≤5 & control≥3)만 남겼다.**

## 실제 플레이 제보로 잡은 버그

> "주공이 리드 컬러 다이아로 다이아 A 를 냈는데 마이티 프렌드가 나와버렸다.
>  리드 A 는 질 일이 없잖아"

원인은 `likelyAlly` 한 줄이었다.

```ts
if (view.declarer === player) return false;   // ← 내가 프렌드여도 주공을 적으로 본다
```

프렌드 입장에서 주공은 아군인데 무조건 false 를 돌려줘서,
**주공이 이미 이기고 있는 트릭에 마이티를 던졌다.**

고친 뒤 (600판):

```
여당 성공률   55.6% → 64.7%
평균 획득     13.38 → 13.99
마이티 낭비   프렌드 응수 4570 중 14회 (0.3%)
```

측정 지표가 멀쩡해 보여도 이런 건 안 잡힌다 —
**사람이 한 판 둬보고 "이건 이상한데" 하는 쪽이 훨씬 빠르다.**

## 아직 못 하는 것

정직하게 적어둔다.

- **티츄 봇이 여전히 약하다.** 여기까지는 전부 점진적 개선이고, 체감할 만한 도약은
  탐색 기반(L3 MCTS + 결정화)이 필요하다. 별도 과제다
- 티츄 핸드 분할이 **여전히 탐욕적**이다. 우선순위 4가지를 돌려 가장 나은 걸 고르지만
  완전 탐색은 아니다
- 티츄는 상대 손패 추론이 없다 (마이티만 보이드를 본다)
- 마이티 프렌드 **확정** 추론은 없다 — 확률적 가정(2/3)만 쓴다
- 상대의 티츄 선언을 방해하지 않는다
